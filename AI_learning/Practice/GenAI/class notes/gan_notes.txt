Short answer: ReLU (Rectified Linear Unit) is a simple, piecewise-linear activation that outputs 0 for negative inputs and the input for positive inputs; tanh is a smooth, S-shaped activation that squashes inputs to the range (−1, 1). ReLU is non‑saturating for positive inputs (favors faster training, sparse activations) while tanh is zero‑centered but saturates for large |x| (can cause vanishing gradients).

Details and comparison

Definitions & formulas
ReLU:
f(x) = max(0, x)
Range: [0, +∞)
Derivative: f'(x) = 1 for x > 0, 0 for x < 0 (undefined at x = 0; set to 0 or 1 in practice)
tanh:
f(x) = (e^x − e^(−x)) / (e^x + e^(−x)) = 2·sigmoid(2x) − 1
Range: (−1, 1)
Derivative: f'(x) = 1 − tanh(x)^2 (largest at x ≈ 0, near 0 for large |x|)
Key properties & implications
Zero-centering:
tanh is zero-centered (outputs negative and positive), which can help gradient-based optimization (symmetry).
ReLU outputs are non-negative (not strictly zero-centered), but often still works well.
Saturation & vanishing gradients:
tanh saturates for large |x| → gradients approach 0 (can slow/stop learning for deep nets).
ReLU does not saturate for positive x (avoids vanishing gradient there), so gradients stay strong for positive activations.
Sparsity:
ReLU produces sparse activations (exact 0 for negative inputs) which can help representation and efficiency.
tanh rarely yields exact zeros.
Computational cost:
ReLU is cheaper (simple max) and numerically stable.
tanh uses exponentials (more compute).
Dying ReLU problem:
If many neurons receive negative inputs and gradients push their weights so they remain negative, they can become permanently inactive (output 0); mitigated by variants (LeakyReLU, Parametric ReLU) or careful initialization/learning rate.
Range & scaling:
tanh bounds activations to (−1, 1), which can be helpful for outputs or when you need bounded activations.
ReLU can produce arbitrarily large positive outputs—useful with batch normalization or controlled weights.
Typical uses / recommendations
ReLU (and variants) — default for hidden layers in most modern deep nets (CNNs, many MLPs): fast convergence, simple, works well with BatchNorm and modern optimizers.
tanh — useful in smaller networks, RNNs (historically used in LSTM gates or when you need centered outputs), or when you need bounded outputs / smoother activations.
If you see vanishing gradients with tanh in deep networks, try ReLU + batch norm or residual connections.
Practical tips
To avoid dying ReLU: use LeakyReLU, Parametric ReLU, careful initialization (He initialization), or lower learning rate.
For tanh: use Xavier/Glorot initialization to keep activations in non-saturated region.
For networks that require outputs in (−1,1) (e.g., some generative decoders), use tanh at the final layer (or scale outputs accordingly).
Quick numeric examples (Python)
NumPy:
ReLU: relu = np.maximum(0, x)
tanh: t = np.tanh(x)
TensorFlow:
tf.nn.relu(x)
tf.nn.tanh(x) or tf.math.tanh(x)
Compact comparison table
Aspect | ReLU | tanh
-------|------|-----
Range | [0, ∞) | (−1, 1)
Derivative | 0 or 1 (sparse) | 1 − tanh^2(x) (smooth)
Saturation | no for x>0 (but zero for x<0) | yes for large |x|
Zero-centered | no | yes
Sparsity | yes | no
Typical use | hidden layers (CNNs, deep nets) | gates, smaller nets, when zero-centered/bounded outputs needed
Problem | dying ReLU | vanishing gradients for deep nets

class VAELossLayer(layers.Layer):
Defines a custom Keras layer that computes and attaches the VAE loss to the model.
def call(self, inputs):
call defines forward computation for the layer.
x, x_recon, z_mean, z_log_var = inputs
Unpacks inputs: original input x, reconstructed output x_recon, latent mean and log variance.
reconstruction_loss = tf.reduce_mean(tf.keras.losses.binary_crossentropy(x, x_recon)) * 784
Computes binary crossentropy per pixel between original and reconstruction.
tf.keras.losses.binary_crossentropy returns mean over last axis (per sample); they take mean across batch and multiply by 784 to convert to total reconstruction loss per image (since BCE returned per-pixel mean).
Multiply by 784 scales loss to total pixel-wise sum equivalent.
kl_loss = -0.5 * tf.reduce_mean(tf.reduce_sum(1 + z_log_var - tf.square(z_mean) - tf.exp(z_log_var), axis=1))
Computes KL divergence between approximate posterior N(μ, σ^2) and prior N(0, I) for each sample: KL = -0.5 * sum(1 + log σ^2 - μ^2 - σ^2)
reduce_sum(..., axis=1) sums over latent dims per sample; then reduce_mean averages over batch.
self.add_loss(reconstruction_loss + kl_loss)
Adds the total loss to the layer; Keras accumulates it and uses it when compiling/training model.
return x_recon
Returns the reconstructed output to pipeline; layer acts as an identity for outputs but adds loss side-effect.
outputs = VAELossLayer()([inputs_dense, reconstruction, z_mean, z_log_var])
Instantiates and applies VAELossLayer to the tensors — effectively connects loss into model graph.
vae = models.Model(inputs_dense, outputs, name="vae")
Rebuilds vae model to have outputs equal to the output of the VAELossLayer (same as x_recon) — this model has loss attached via layer's add_loss.
